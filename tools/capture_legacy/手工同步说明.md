# 旧数据采集工具：冻结交付

两个脚本保持原字节，不进行更新，也不与 v28 BTE1 桥接同时运行。

serial_imu_capture.py 版本2.2.0面向旧 @IMU1 六轴采集固件，依赖 Python、pyserial、opencv-python。
示例（只用于匹配旧采集固件）：
`python serial_imu_capture.py --serial-port COM7 --baud 1000000 --camera-index 0 --duration-s 30 --require-six-axis --output-dir captures/新的会话名`
该工具观察NSH后会发送 openvela_ble_probe，必须事先确认固件/串口状态；不能拿该命令启动v28 BTE1采集。

手工同步流程：1. 记录摄像头/串口/固件标识和拍号BPM；2. 采集开始静止约2秒，再做3个清晰可见的下拍；3. 保留视频、原始串口、CSV和元数据；4. 人工标记视频帧时间与IMU峰值，按相同3次动作估算偏移；5. 另存对齐表记录帧号、IMU序号、偏移和不确定性，不覆盖原数据；6. 若3次对应关系不唯一，标为无法可靠对齐，不推算精确延迟。
脚本明确声明 video/IMU 非硬件同步，本流程也不是设备与主机时钟校准。

capture_front_camera_ble_accel.py 是更早BLE/视频采集工具，依赖 bleak、opencv-python，可选pyserial。必需参数 --address、--output-dir、--meter、--bpm；其余以源码参数表为准。本次只保留，不作为v28采集入口。历史依赖精确版本未形成锁文件，不能声称已复现。
